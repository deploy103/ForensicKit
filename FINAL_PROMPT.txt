현재 저장소는 CTF 현장에서 사용할 오프라인 디지털 포렌식 자동화 플랫폼 `ForensicKit`을 개발하기 위한 초기 저장소다.

당신은 이 저장소의 구현을 끝까지 담당하는 주 개발 에이전트다.

먼저 반드시 다음 파일을 처음부터 끝까지 읽어라.

1. AGENTS.md
2. 요구사항.md
3. TOOL_CATALOG.md
4. config/tool-catalog.yaml
5. config/rules.example.yaml
6. install_forensics.sh
7. README.md

그 후 현재 저장소 전체 구조와 기존 코드를 조사하라.

## 최종 목표

사용자가 CTF 문제 파일을 하나 입력했을 때:

Evidence 보존
→ Hash
→ Magic/MIME
→ Generic triage
→ Artifact classification
→ Observation
→ Rule/Profile 판단
→ Tool planning
→ 적절한 외부 포렌식 툴과 옵션 실행
→ 결과 parsing
→ Finding
→ 추출 파일 등록
→ Recursive analysis
→ Flag candidate 탐지
→ Artifact lineage
→ report.json/report.md

까지 가능한 한 자동으로 진행하는 완전 오프라인 프로그램을 완성한다.

이 프로그램은 단순히 포렌식 명령어를 여러 개 감싼 wrapper가 아니다.

핵심은 현재 아티팩트와 관찰 결과를 바탕으로 어떤 툴을 어떤 옵션으로 언제 실행해야 하는지를 결정하는 deterministic 분석 엔진이다.

대회 환경에서는 AI와 인터넷을 사용할 수 없으므로 최종 프로그램에는 LLM/API/외부 네트워크 의존성을 절대 넣지 마라.

## 개발 권한 및 방식

저장소 내부 코드는 필요하면 대규모로 수정/추가/삭제해도 된다.

사소한 구현 선택 때문에 사용자에게 계속 질문하지 마라.
요구사항에서 답을 얻을 수 없으면 유지보수성과 실제 CTF 사용성을 기준으로 합리적인 기본값을 선택하고 계속 진행해라.

단계별 계획만 작성하고 멈추지 마라.
계획을 세운 뒤 실제 구현, 테스트, 수정까지 이어서 진행한다.

## Tool Integration

`config/tool-catalog.yaml`은 초기 seed다.

실제 머신에 설치된 툴을 조사하고 Tool Registry를 확장하라.

`install_forensics.sh` 역시 검토 대상이다.
패키지명, binary name, 설치 위치, version probe 등이 실제 구현과 일치하도록 필요하면 수정하라.

특히 우선 지원:

- file
- ExifTool
- Binwalk 3 / binwalk fallback
- 7z
- pngcheck
- zsteg
- steghide
- stegseek
- foremost/scalpel/bulk_extractor
- tshark/capinfos
- SleuthKit
- EWF/XMount
- Volatility 3
- pdfid/pdf-parser
- oletools/oledump
- RegRipper
- Hayabusa
- Chainsaw
- ALEAPP
- iLEAPP
- sqlite3

외부 명령은 shell string concatenation보다 argv list로 안전하게 실행한다.

툴이 없으면 전체 분석이 죽지 않아야 한다.

## Decision Quality

각 자동 실행에는 설명 가능한 근거가 있어야 한다.

예:

[+] PNG signature detected
[+] IEND found at 0x18320
[!] 10342 bytes exist after IEND
[+] PK signature found at 0x183A2

Hypothesis:
  Possible appended ZIP

Selected tools:
  binwalk3 — embedded signature/offset verification
  7z       — archive validation/extraction
  zsteg    — additional PNG stego analysis in deep mode

이런 식으로 관찰 → 판단 → 실행이 연결되어야 한다.

## Output Parsing

raw stdout/stderr만 사용자에게 던지지 마라.

중요 포렌식 툴에는 parser를 구현해서 Observation/Finding/Artifact를 생성하라.

동시에 원문 stdout/stderr는 반드시 workspace에 보존한다.

## Recursive Analysis

추출된 파일은 child artifact로 등록하고 필요하면 다시 분석한다.

SHA256으로 deduplicate한다.

archive bomb 및 무한 recursion을 막아라.

설정:

- max depth
- max artifact count
- max extracted bytes
- max single artifact size
- per-tool timeout
- jobs

을 구현한다.

## Flag Hunter

기본:
- CTF{...}
- FLAG{...}

사용자 지정 flag pattern을 지원한다.

ASCII/UTF-8/UTF-16과 evidence-driven Base64/Hex/URL/ROT13/gzip/zlib 변환을 지원한다.

변환 chain과 원본 위치를 기록한다.

무제한 brute force는 하지 않는다.

## Offline Bundle

최종적으로 다음을 구현하라.

scripts/build_offline_bundle.sh
scripts/install_offline.sh

동일한 distro/version/architecture 기준으로 인터넷 가능한 준비 머신에서 필요한 의존성을 수집하고,
인터넷 없는 대회 머신에서 복구/설치할 수 있게 한다.

필요하면 distro별 manifest를 생성한다.

오프라인 번들은 가능한 범위에서:
- deb
- Python wheels
- Ruby gems
- standalone tools
- Volatility symbols
- YARA/Sigma rules
- mobile parsers

를 포함한다.

→ appended ZIP

→ Flag

### E2E 2
PCAP
→ HTTP object

→ Flag

### E2E 3
OOXML/OLE

→ encoded Flag
